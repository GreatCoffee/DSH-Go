## 4. The four workflows

### 4.1 Build

**A short path is mandatory**, otherwise the built-in Python's `lxml` reports `DLL load failed while importing _elementpath: 文件名或扩展名太长` for exceeding 260 characters.

```powershell
# 1) 复制源码到短路径（不要复制 node_modules）
robocopy 'D:\Documents\Softwares\DSH-Go\portable\workspace\DSH-Portable\dsh-go' 'D:\b\dsh-go' /E /MT:16 /XJ /XD node_modules .desktop-build dist .pnpm-store

# 2) 装依赖
cd D:\b\dsh-go
pnpm install --frozen-lockfile

# 3) 构建并组装便携目录
pwsh scripts/build-portable.ps1
# 产物：D:\b\dsh-go\dist\DSH-Go（约 1,081 MB）
```

It takes about 5 minutes. Delete `D:\b` after the build completes.

### 4.2 Release

```powershell
cd D:\b\dsh-go
pwsh scripts/release-portable.ps1 -SkipBuild
```

- Tag rule: `go-<build commit hash>` (the hash comes from `dist\DSH-Go\BUILD-INFO.txt`)
- Assets: `DSH-Go-<commit>-win-x64-portable.zip` + `.sha256`
- Uploading takes about 2 minutes; after publishing, confirm on the release page that the assets are `uploaded` and not a draft

### 4.3 Update (user perspective)

```powershell
# 完全退出 DSH-Go 后：
D:\Documents\Softwares\DSH-Go\Update-DSH-Go.cmd
```

- Logic: read the `BUILD-INFO` commit hash → resolve the `releases/latest` redirect → download → verify SHA-256 → replace the program files with robocopy (`/XD portable`) → restart
- Log: `update-last.log`
- Refuses to update while the app is running; `-Force` force-stops it; `-Check` only checks; `-NoPause` does not pause

### 4.4 Following upstream

```powershell
pwsh scripts/sync-upstream.ps1 -DryRun   # 看落后多少
pwsh scripts/sync-upstream.ps1           # 合并（或 -Rebase）
pnpm install --frozen-lockfile
pnpm exec tsc -b apps/desktop/tsconfig.host.json packages/api/workspace-controller/tsconfig.host.json
pwsh scripts/build-portable.ps1          # 在短路径副本里
```

The conflict surface is fixed at four places: `apps/desktop/src/main.ts` (the hook), `apps/desktop/package.json` (one devDependency), `packages/api/workspace-controller/src/default-directory.ts` (the environment variable), `.github/dependabot.yml` (deleted in this repository, kept upstream).

## 5. Known pitfalls (in the order encountered)

1. **Long paths**: see 4.1, the build must use a short path.
2. **Copying the repository must not follow `node_modules`**: the repository uses pnpm's symlink layout, and copying with follow expands to over 40 GB (measured 43.75 GB / 3.78 million files). Always use `/XD node_modules` + `/XJ`.
3. **PowerShell scripts must be UTF-8 with BOM**: 5.1 decodes BOM-less Chinese as GBK, which causes mismatched quotes, parse failures, and flashing console windows.
4. **Batch files must use CRLF**: a `.cmd` with LF makes cmd.exe skip entire command lines. The repository's `.gitattributes` already has `*.cmd text eol=crlf`, but confirm it is still CRLF after checkout.
5. **Do not use `$home` as a variable name**: it is a PowerShell automatic read-only variable (= the user directory). See the incident in section 6.
6. **`gh` misjudges the repository**: when the repository also has an `upstream` remote, `gh release` may resolve to the official repository; always pass `--repo GreatCoffee/DSH-Go` explicitly.
7. **API rate limiting**: anonymous calls to the GitHub REST API get rate-limited, which is why the updater was changed to resolve the `releases/latest` redirect; do not change it back.
8. **Empty-shell sessions**: sessions with only a header and no events used to be undeletable in the UI and had to be deleted at the `sessions\<projectKey>\session-*` level with `storages\session_projcache` cleared. There is now "Delete session" in the session menu (`@deepseek-ai/dsh-go-session-delete`); use it for shells that can be listed but not deleted, and fall back to deleting the directory by hand only for leftovers that cannot even be listed.
9. **The release stays Draft during publishing**: `gh release create` with a 407 MB asset takes over ten minutes; meanwhile `isDraft` returns `true` and `assets` contains only the already-uploaded `.sha256`; it flips to published and Latest only when the upload finishes. Do not treat it as a failure and rerun.
10. **`netstat -e` counters wrap at 4 GiB**: cumulative bytes dropping from 4,142,064,790 to 335,306,974 is a counter rollover, not a network drop; the only way to tell whether the upload is moving is the delta between adjacent samples.
11. **Plugin state lands in the user directory by default**: XDG-aware plugins (such as billion-context) write to `~/.config`, `~/.cache`, `~/.local/state`. The portable build already points `XDG_CONFIG_HOME`/`XDG_CACHE_HOME`/`XDG_STATE_HOME` at `portable\config|cache|state` in `applyPortableEnvironment`; copies left in the user directory before the upgrade must be moved by hand.

## 6. Data boundaries and incidents

**Where personal data lives** (not in portable, do not package it):

- Desktop `D:\Desktop`, documents `D:\Documents`, downloads `D:\Downloads` (the C: drive user directory holds redirected empty shells)
- Credentials `portable\dsh-home\.credentials.yaml` (plaintext, moves with the package, must be confirmed absent before a release)

**Pre-release checklist**: `dist\DSH-Go\portable` contains only the empty directory skeleton; `BUILD-INFO.txt` has no personal information; a scan of text files for `GreatCoffee`, `C:\Users`, `Documents\Softwares` finds no hits.

**2026-11-06 incident**: while cleaning a temporary directory, the `$home` variable was misused and a recursive delete was executed against `C:\Users\GreatCoffee`, partially deleting the configuration directory. Restored from the 06:03 system volume shadow copy: 26 top-level items, 55 AppData subdirectories, and 10,090 missing files were all restored, without overwriting any newer file.

**Three rules fixed by it**: before a destructive command, print and assert that the absolute path falls within the expected prefix; start scripts with `$ErrorActionPreference='Stop'`; prefer moving to `.trash-<timestamp>` before deleting.

# @deepseek-ai/dsh-go-maintenance

[English](README.md) | 中文

<p align="center"><b>DSH-Go 存储维护：清理删除会话后可能留下的残留。</b></p>

## 概要

设置页里的一个分区，统计并清理三类残留：已不再被任何工作区引用的投影缓存检查点、不再被任何工作区引用的会话日志目录、以及没有任何会话日志引用的图片附件。全部按需执行——每次启动都扫一遍，装得越久越慢，所以这里由按钮驱动宿主端的两个 Remote（`goMaintenance.scan`、`goMaintenance.clean`）。

不做猜测。某一类如果无法确证，就报告为空：会话日志读不出来、或持久化后端根本不落目录，都宁可不清，也不释放别的会话还可能需要的数据。

## 使用本包

打开**设置 → 维护**，点**扫描**，再单独清理某一行或全部清理。每行显示清理能回收多少；清理后会重新扫描，让数字与磁盘一致。

本页随 DSH-Go 便携版一起提供。和安装包里的其他 bundle 一样，它能在插件管理器里关闭，重新开启不需要重启宿主。

## 实现说明

<details>
<summary>三类残留是怎么找出来的</summary>

- 存活判定看工作区，不看存储：所有工作区的 `sessionIds`，加上注册表的归档集合与置顶集合。后端仍列出、但没有任何工作区拥有的日志，正是本页要清的残留——把它算作存活，第一版就永远报 0。如果一个工作区都没引用任何会话，扫描报空，而不是把一个完整的安装当成残留。
- 投影记录：检查点表位于 `session_projcache` 域，缓存服务终身持有该域；域设施只允许打开一次，所以本包向该服务要数据（`orphanIds(known)` 与 `pruneOrphans(known)`），而不是自己再开一次表。
- 会话目录：`SessionPersistence.root` 给出后端写入的根目录。没有工作区拥有该会话，目录就是残留——无论当前写法 `session-<id>` 还是旧版本的 `<id>`。删除前会先问 `workspace/session-activity` 的提供者该 id 上是否仍有任务在跑，有就跳过。
- 附件：图片对象按内容寻址（`sha256:<hex>`）。逐页读取每个仍在存储中的会话日志，收集出现的摘要；没有日志提到的对象才算残留。读取失败会让本次附件扫描整体放弃，因为无法证明的引用必须保留文件。这一类刻意保守：只要还有一份存活日志提到该摘要，就绝不删。
- 每次清理都会通过 `console` 往宿主日志写一行审计记录（便携版即 `portable/logs/host-<日期>.log`），因为 `ctx.logger` 的输出到不了那个 tee。

</details>

## 模型体验

维护页是设置分区，不含工具，也不含提示词。用户打开它时模型才会看到。

## 已知限制与后续工作

- 附件目前只覆盖 `attachments/v1/objects` 下的图片对象。文件块（`files/`、`file-objects/`）与请求图片缓存尚未扫描：它们的清单带着引用名，粗暴按目录清理可能误删别的会话仍在显示的文件。
- 投影记录只计数、不计体积，清理后报告无法给出对应字节数。
- 成本台账会刻意保留已删除会话的计费历史，这里不做改动。

## 开发说明

宿主半边：一个 `TypertRemoteService`（`goMaintenance`），带 `@Remote('scan')` 与 `@Remote('clean')`。浏览器半边：一条 `settings.section` 注册；通过 `@deepseek-ai/dsh-api-remotes` 挂载的 `goMaintenance` 命名空间访问宿主。
